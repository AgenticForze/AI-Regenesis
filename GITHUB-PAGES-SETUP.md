# GitHub Pages Setup & Site Status

This repo serves as a real, SEO-crawlable Jekyll site directly from GitHub Pages, zero external hosting
needed. It's live at **https://agenticforze.github.io/AI-Regenesis/**.

## Current status: configured and live

- `docs/_config.yml`'s `url`/`baseurl` are set for the current deployment — no placeholders left.
- Pages is serving from `main` / `/docs`.
- Favicon, OG/Twitter social preview image, and a branded 404 page are all in place (see "Polish pass"
  below).

If you ever fork this, rename the repo, or move it to a different account, the two things that need
updating are `docs/_config.yml`'s `url:`/`baseurl:` and the `SITE_URL`/`GITHUB_REPO_URL` constants near the
top of `scripts/build.py` (used to fill in the homepage's OG-image URL and "Full markdown source" links,
which can't use Jekyll's own `site.url` since that template has no Jekyll front matter) — then run
`python3 scripts/build.py` and push.

## Verify the build is healthy

Check the **Actions** tab — a "pages build and deployment" workflow run should show a green checkmark. If
it's red, it's almost always a YAML syntax issue in `docs/_config.yml` from a manual edit. Everything else
has been validated locally before every push in this project's history: all generated pages' front matter
parses as valid YAML, and every download/asset link is checked against a real file on disk.

## Polish pass — what changed and why

- **Favicon was entirely missing** (`_config.yml` referenced one, no file existed) — added
  `docs/favicon.svg`, wired into the shared layout's `<head>`.
- **OG/Twitter image was a broken reference** (`og-image.png` didn't exist; link shares showed no preview)
  — designed and rendered a real 1200×630 image reflecting the actual product, referenced as an absolute
  URL (relative OG image URLs are unreliable across social platforms).
- **The homepage's "Full markdown source" links were broken** — they pointed at `docs/{path}`, a URL that
  doesn't exist once GitHub Pages serves `/docs` as the site root (the real page lives at `/{path}` with no
  `docs/` prefix and no `.md` extension). Repointed them at GitHub's own file viewer
  (`github.com/.../blob/main/{path}`), which is also a better fit for "view the raw source" than linking to
  the already-being-viewed rendered page.
- **No 404 page** — GitHub Pages was falling back to its generic default. Added a branded one at
  `docs/404.html` with links back into the site.
- **Homepage payload size** — `docs/index.html` is ~4MB uncompressed (~585KB gzipped, which is what actually
  transfers, since GitHub Pages serves gzip automatically). That's the cost of inlining all 120 use cases for
  instant client-side search with no backend. Left as-is rather than rearchitected in this pass — a real fix
  (lazy-loading per-domain JSON on demand) is a bigger, riskier change to the hand-built SPA than the other
  items here, and 585KB over the wire isn't broken, just heavier than ideal. Worth revisiting if it's ever
  reported as an actual load-time complaint.

## When you buy a custom domain later

1. Add a file `docs/CNAME` containing just the domain, e.g.: `ai-regenesis.ai`
2. In `docs/_config.yml`, change `url:` to `https://ai-regenesis.ai` and delete the `baseurl:` line entirely
3. Update `SITE_URL` in `scripts/build.py` to match, then rerun `python3 scripts/build.py`
4. Point your domain's DNS at GitHub Pages per
   [GitHub's custom domain docs](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site)
5. In repo Settings → Pages, GitHub will detect the CNAME file and prompt you to enforce HTTPS — turn that on
